How AadiCrypto is put together

Live market data for the top hundred coins, served from the edge for nothing a month. This describes what is actually running, what is deliberately still a placeholder, and the reasoning behind both.

Frontend TanStack Start (SSR) Runtime Cloudflare Workers Cache Cache API, per datacentre Cost ₹0 / month

01 — Where things stand

What is real and what is a placeholder

This is the part most architecture documents leave out, and it is the part that matters when someone else opens the repository. Every figure on the site is live. Every story is a placeholder that says so.

02 — The shape of the problem

Three kinds of data, one page

The top strip carries live market numbers. The middle of the page will carry stories. The nav, footer and Learn pages barely change at all. They arrive on one screen, so it is tempting to treat them the same way. Don't.

If a page waits on live prices, every article becomes slow, and slow articles do not rank. Split them at the start and each gets the cache it deserves.

KindWhere it showsChangesHow it is served
Market data Top ticker, snapshot cards, the Crypto Market table seconds One fetch per datacentre per minute; everybody reads that copy
News Everything under /news, topic and coin hubs ~5 min Will live in our own store, cached hard, cleared on publish
Editorial furniture Nav, footer, taxonomy, Learn pages rarely Compiled into the build, cached for hours

03 — Rendering

Server rendering was already solved

Correction to version 1

Version 1 of this document recommended moving the frontend to Next.js so pages would render on the server. That recommendation was wrong for this project. The app is built on TanStack Start, which already renders on the server.

Checked rather than assumed: a plain request to the deployed site returns 149 KB of real HTML with the headline, the ticker figures and the meta tags all present. There was never a migration to do.

So a crawler asking for a page gets the finished article on the first request, which is what Google News and Discover need. Route-level head() blocks already set per-page titles, descriptions and Open Graph tags.

What is still owed for search: a sitemap, a news sitemap, an RSS feed, and NewsArticle structured data on each story. All of those wait on the newsroom, because there is nothing yet to put in them.

04 — The stack

How a price reaches the page

There is no server to maintain. The whole application — page rendering and the market API together — is one Cloudflare Worker, running in whichever datacentre is closest to the reader.

05 — Caching

The browser never calls a third-party API

The Worker fetches prices once a minute and keeps the result in the Cache API. Everything else reads that copy. Nothing else touches the upstream.

Calling a price API straight from React looks easier for about a week. Then the key is sitting in your JavaScript bundle where anyone can read it, the provider starts throttling because ten thousand browsers are each asking separately, and you cannot cache a response you never controlled.

Moving to the edge changed one number in that design. On a single Node process, one cache serves every reader on earth, so a ten-second refresh is affordable. On Cloudflare there is no single process — each active datacentre keeps its own cache and refreshes independently, so the same ten seconds multiplies by however many datacentres are serving traffic.

CoinGecko's free tier allows thirty calls a minute. Each refresh costs two. The arithmetic decides the TTL:

Reads are stale-while-revalidate inside a bounded window. Once a copy is stale we hand it back immediately and refresh alongside, so a slow upstream never blocks a render. Past a hard ceiling of three minutes we stop pretending and wait for fresh data — necessary because Workers may cancel work started after a response has been sent, and without that ceiling the data could stick forever.

06 — Layer by layer

What each piece is responsible for

Five pieces. Each has one job, and each can be replaced without touching the others.

  1. 01 — THE PROVIDER ADAPTER

    Everything CoinGecko-shaped lives in one file

    market-source.ts is the only file that knows what CoinGecko returns. It converts the provider's shape into ours, so swapping to CoinMarketCap means editing one file rather than fifty.

    It walks our own coin list rather than the provider's, so a missing coin can never silently reorder the table. A failed fetch returns the last good copy marked stale, and if nothing has ever succeeded it returns a clearly-labelled demo set rather than an error page.

  2. 02 — THE CACHE

    One interface, two runtimes

    market-cache.ts hides the difference between a Node process and a Cloudflare isolate. On Node it is a Map. On Workers it is the Cache API, which is free, unmetered and shared by every request hitting the same datacentre.

    This matters more than it looks. Module state on Workers is not a cache, it is a coincidence — an isolate can be destroyed between any two requests. Keeping that detail behind one small interface is what lets the same code run on a VPS later without edits.

  3. 03 — SEPARATE CLOCKS

    Slow-moving data gets slow-moving caches

    Prices refresh every minute. Trending coins every ten minutes. Sector membership — which coins count as DeFi or AI — every six hours. Fear & Greed every hour, because it only publishes once a day.

    Putting these on one clock is what produced the first round of rate-limit failures: seven calls firing together, every refresh. On their own clocks they are four calls twice a day.

  4. 04 — THE API AND THE PAGES

    Both read the same cache

    Server-rendered pages call the cache directly, so the HTML leaves with real numbers already in it. The browser then polls /api/v1/market/ticker, which reads the same cache. One source of truth, two ways in.

  5. 05 — THE EDGE

    Cloudflare absorbs the repeat traffic

    Every API response carries its own Cache-Control, so most requests are answered by Cloudflare before they reach our code at all. This is what lets a free plan serve a real audience, and it comes with TLS, bot filtering and DDoS protection at no cost and no configuration.

08 — Security

Smaller surface than a server

Moving to Workers deleted most of the original list. There is no box to patch, no SSH to lock down, no database port to leave open by accident. What remains:

AreaWhat to do
API keysStored with wrangler secret put, encrypted at Cloudflare. Never a VITE_ or NEXT_PUBLIC_ variable — those are compiled into the bundle for anyone to read.
Verify itAfter each build, grep the client bundle for the provider host and the key name. Both should return zero files. The only thing the browser should know about is /api/v1/market/ticker.
Server-only codeTanStack Start blocks any import from src/server/ into client code, and fails the build if you try. Keep genuinely secret logic there and the compiler enforces it for you.
Local secrets.env and .dev.vars are gitignored; only .env.example is committed, with no values in it.
CORSNo cross-origin header is set, so the API is same-origin by default. A read-only API is not a reason to open it.
Rate limitingCloudflare's free tier covers the basics. Worth a rule on /api/* before the newsroom brings real traffic.
Feed contentWhen the newsroom lands: sanitise HTML pulled from RSS before storing it. Feeds carry scripts, and that is a real route into your own pages.
Admin panelWhen it exists: its own subdomain, behind login and two-factor. Never sharing a session with the public site.

09 — Hosting

Cloudflare Workers, nothing a month

Correction to version 1

Version 1 planned a Hostinger VPS with Docker Compose, Nginx, PostgreSQL and Redis. The available plan turned out to be Premium Web Hosting, which is PHP and MySQL only — it cannot run a Node process at all. Hostinger offers Node.js on Business and Cloud plans, not Premium.

Rather than pay for an upgrade that would still be outgrown once the newsroom needs a database, the whole application moved to Cloudflare Workers. It costs nothing, it is faster, and the build already targeted it.

Two commands do everything:

npm run preview:cf   # build, then run the real Worker locally
npm run deploy       # build, then wrangler deploy

# the API key, stored encrypted at Cloudflare, never in the repo
npx wrangler secret put COINGECKO_API_KEY

The Hostinger plan still earns its keep: it holds the domain and the email. Only the application moved.

A Node build is kept alongside — npm run build:node produces a standalone server for a VPS. The cache interface means the same code runs either way, so moving back later is a deployment change rather than a rewrite.

When the newsroom arrives, articles need storage. Cloudflare D1 and Cron Triggers cover it on the same free plan, which keeps the whole thing on one platform. A VPS with PostgreSQL remains the alternative if the editorial side grows past what D1 is comfortable with.

10 — Code layout

Where things live

src/
├── types/market.ts              the wire contract, shared by both sides
├── server/                      blocked from client imports by the build
│   ├── market-source.ts         fetch · normalise · fall back
│   ├── market-cache.ts          Cache API on Workers, Map on Node
│   └── api.ts                   GET /api/v1/market/ticker
├── lib/market-fn.ts             server fn — must sit outside server/
├── routes/                      file-based, SSR, per-route meta
├── components/site/
│   ├── useMarketTicker.ts       one shared poll, deduped
│   └── ComingSoon.tsx           honest placeholder
└── data/                        taxonomy and editorial lists

types/market.ts matters more than it looks. When the API and the pages share one set of types, a breaking change fails at build time instead of appearing as a blank widget on the live home page.

lib/market-fn.ts sits outside server/ on purpose. The build refuses any client import from server/, and the server-function bridge has to be importable by the client — the plugin swaps it for a remote call there.

11 — What real data taught us

Five things no amount of planning would have caught

Each of these was found by running the thing, not by thinking about it. They are recorded because every one of them would otherwise be rediscovered the expensive way.

  1. 01 — 403, NOT 429

    Workers send no User-Agent

    CoinGecko rejects requests without one. Node happens to send a default, so this worked perfectly in local development and failed everywhere else. Upstream calls now set an explicit User-Agent.

  2. 02 — NO I/O AT MODULE SCOPE

    A cache-warming call would have failed the deploy

    Warming the cache at boot is sensible on a Node server and forbidden on Workers, which reject any I/O in global scope. One line, written for the old runtime, would have broken the first deploy outright.

  3. 03 — SUB-CENT COINS

    $0.0000

    Price formatting capped at four decimal places. With ten hand-picked coins nothing traded that low; with the real top hundred, SHIB and PEPE both flatlined to zero. They now render eight decimals.

  4. 04 — A 200 IS NOT ALWAYS SUCCESS

    An empty list poisoned a six-hour cache

    A sector endpoint returning 200 with an empty array was treated as a good answer and cached, blanking that tab until the next restart. Success now requires actual rows.

  5. 05 — RATE LIMITS ARE BURSTY

    Seven calls at once earns a 429

    The per-minute allowance is not the whole story. Firing every call together reliably failed even while well under the stated budget. Splitting slow-moving data onto its own clocks fixed it, and a free demo key raised the ceiling from roughly ten calls a minute to thirty.

12 — Still open

Decisions the newsroom will force

The architecture above holds either way on all of these, but they shape what gets built next.

  • Where the news comes from. Written in-house, pulled from feeds, or both. Pure aggregation has copyright limits; a mix is usually the safest place to land.
  • Where articles are stored. Cloudflare D1 keeps everything on one free platform. PostgreSQL on a VPS is more familiar and more capable. This is the next real fork.
  • Whether editors need an admin panel, or the pipeline runs unattended.
  • How India-focused the site is. There is an India section and INR pricing already, which changes both the price source and the feed list.
  • When to lift noindex. Recommended: once the newsroom has real stories, not before.
  • The "New" market tab is gone for now — the free tier has no recently-listed feed, and an invented one is worse than none.
